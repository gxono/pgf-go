\def\karu{K\={a}ru}

\section{The Boards of \karu}

\subsection{Board and Stones}

\karu\ is writing an article to share with his students. He has noticed that diagramming \emph{software} does not offer satisfactory formats or results. Therefore, he decides to try \pgfgoname\ and starts by representing a game like the one shown in Figure~\ref{fig:first-example}.

\begin{figure}[H]
	\centering
	\pgfgoset{profile = pgfgo}
	\begin{goban}[use i = false, label = {at = {north, west}}]
		\stones[black]{B2,E2,J2,C3,D3,G3,H3,C5,D5,E5,F5,G5,E6,G6}
		\stones[white]{D8,F8,E7,H7,C6,D6,F6,H6,B5,J5,B4,E4,J4,J3,H2}
	\end{goban}
	\caption{}
	\label{fig:first-example}
\end{figure}

\karu\ must start with the board. In \pgfgoname, there is currently a single environment where elements can be placed: |goban|. This environment controls by default the size and color of the board, the position and type of labels, among other properties. It also allows partial board representations.

\begin{codeexample}[width=4.4cm]
	\begin{goban}
	\end{goban}
\end{codeexample}

\karu\ is satisfied. The environment provides a default $9\times 9$ board, which is exactly what he needs, but he must add side labels. The |goban| environment does not require mandatory parameters, although it accepts an optional one: a list of |keys| or |key=values| for configuration. \karu\ consults the section on |goban| (p.~\pageref{sec:board}) and decides to add labels to the environment. He knows that the \emph{keys} controlling the objects in the goban are divided into three groups: |grid|, for the central grid; |background|, for the border and board fill; and |label|, for coordinate labels. The latter is the one that interests him. This \emph{key}, among other options, can take the \emph{key} |at| to define the label position with values such as |above|, |west|, |below|, |right|, |all|, or |none|. Cardinal points can also be used. Since he only wants labels above and to the left of the goban, he will use the \emph{keys} |above| and |left|.

\begin{codeexample}[width=4.7cm]
	\begin{goban}[label = {at = {above, left}}]
	\end{goban}
\end{codeexample}

\karu\ feels that everything is going well, but he notices that his board includes an |I| instead of omitting it and going directly to |J|. By default, in \pgfgoname, "I" exists and is used both as a coordinate and in the side labels, although it is possible to remove it. There are two ways to do this: setting |goban/use i| to |false| for every board (|\pgfgoset{goban = {use i = false}}|), which would prevent \karu\ from worrying about this throughout the rest of the article, or applying it directly to the board with the same \emph{key} and value.

\begin{codeexample}[width=4.8cm]
	\pgfgoset{goban = {use i = false}}
	
	\begin{goban}[label = {at = {above, left}}]
	\end{goban}
\end{codeexample}

Now he is ready to place the stones. For this, \karu\ has several macros. Let’s start with the most basic one: |\stone[options]{intersection}|. This command accepts two parameters: the first, optional, controls the appearance and additional elements of the stones (such as marks); the second, mandatory, is the intersection. \karu\ does not need to convert intersections to numbers since he can specify them alphanumerically. By default, the stones are neutral, but he can choose the first player by passing the \emph{key} |black| or |b|.

\begin{codeexample}[width=4.8cm]
	\begin{goban}[label = {at = {above, left}}, use i = false]
		\stone[black] {D8}
		\stone[black] {F8}
		\stone[b] {E7}
		\stone[b] {H7}
	\end{goban}
\end{codeexample}

\karu\ suspects that this is not the best option if he needs to add 200 stones or more. To simplify the syntax, he finds in the documentation the macro |\stones[options]{intersection, intersection, ...}|, which accepts the same optional \emph{keys} as |\stone|.\footnote{Between \texttt{\textbackslash stone\{A1\}} and \texttt{\textbackslash stones\{A1\}}, the first one is much faster. We will see later that many processes are involved in reading the mandatory argument of the plural macros.}

\begin{codeexample}[width=4.8cm]
	\begin{goban}[label = {at = {north, west}}, use i = false]
		\stones[b]{B2,E2,J2,C3,D3,G3,H3,C5,D5,E5,F5,G5,E6,G6}
	\end{goban}
\end{codeexample}

\karu\ also notices that there is a syntax (p.~\pageref{subsec:coordinate-syntax}) to add several coordinates at once. For example, for a line of stones from C5 to G5, he can write |C:G5| or |C5--G5|.

\begin{codeexample}[width=4.8cm]
	\begin{goban}[label = {at = {north, west}}, use i = false]
		\stones[b]{B2,E2,J2,C3,D3,G3,H3,E6,G6,C:G5}
	\end{goban}
\end{codeexample}

To add white stones, \karu\ must include the \emph{key} |white| in the |\stones| command. He knows that |white| and |black| do not literally refer to the colors white and black, but to the second and first player, respectively, and that when these \emph{keys} are applied, the objects inherit their properties.

\begin{codeexample}[width=4.8cm]
	\begin{goban}[label = {at = {north, west}}, use i = false]
		\stones[b]{B2,E2,J2,C3,D3,G3,H3,E6,G6,C:G5}
		\stones[w]{D8,F8,E7,H7,C6,D6,F6,H6,B5,B4,E4,H2,J3:5}
	\end{goban}
\end{codeexample}

Finally, the style of his board remains. For this, he looks through the catalog (p.~\pageref{sec:catalog}) and finds a style he likes: |pgfgo|. To apply it, he reads the section on profiles (p.~\pageref{subsec:profiles}) and decides to use the key |profile|: |\pgfgoset{profile = <name>}|.

\begin{codeexample}[width=4.8cm]
	\pgfgoset{profile = pgfgo}

	\begin{goban}[label = {at = {north, west}}, use i = false]
		\stones[b]{B2,E2,J2,C3,D3,G3,H3,E6,G6,C:G5}
		\stones[w]{D8,F8,E7,H7,C6,D6,F6,H6,B5,B4,E4,H2,J3:5}
	\end{goban}
\end{codeexample}

\subsection{Moves}

When the stones are to be placed in order, following the sequence "black, white, black, white", it can be tedious and unnecessary to give the \emph{key} of each player.

\begin{codeexample}[code only]
	\begin{goban}
		\stone[b]	{F7}
		\stone[w] {E6}
		\stone[b]	{G3}
		\stone[w]	{D6}
	\end{goban}
\end{codeexample}

That is why \pgfgoname\ includes macros that make this easier. Let’s start with the singular one:
\begin{command}{\move\opt{\oarg{options}}\marg{intersection}}
\end{command}
This command works like |\stone|, but alternates the colors automatically.

\begin{codeexample}[width=5cm]
	\begin{goban}[label = {at = all}]
		\move	{F7}
		\move	{E6}
		\move	{G3}
		\move	{D6}
	\end{goban}
\end{codeexample}

The macro |\move|, like |\stone|, has a plural version:
\begin{command}{\moves\opt{\oarg{options}}\marg{intersection}}
\end{command}
In this case, giving the \emph{key} |black| or |white| only sets who is the first player of the sequence.

\begin{codeexample}[width=5cm]
	\begin{goban}[label = {at = all}]
		\stone[b] {F7}
		\moves[white] {	E6,G3,D6,F5,E7,E2,F8,E6,D8,D3,
			G7,C5,C6,D5,B5,G5,B4,B2,H6,C3,
			I3,I2,I5,H3}
	\end{goban}
\end{codeexample}

The macros |\move| and |\moves| also have "starred" versions (|\move*| and |\moves*|), which label the moves. The \emph{key} |from| sets the number where the labels start.

\begin{codeexample}[width=5cm]
	\begin{goban}[label = {at = all}]
		\moves[white] {	E6,G3,D6,F5,E7,E2,F8,E6,D8,D3,
			G7,C5,C6,D5,B5,G5,B4,B2,H6,C3,
			I3,I2,I5,H3}

		\moves*[from = 26]{F6,E5,I4,G6}
		\move* {H2} % Black and labeled 30, without saying so.
	\end{goban}
\end{codeexample}

In this last example, |H2| was placed with |\move*| and, although it is separate from |\moves*|, it is black and labeled 30, because the last stone placed (|G6|) was black and labeled 29.

\subsection{Partial Board and Marks}

Sometimes we want to focus on a particular region of the board. For this reason, it is possible to show only a portion of it.

\begin{figure}[H]
	\centering
	\begin{goban}[partial = B2:E4, background = false]
		\stones[b] {C2,B3,C4}
		\stones[w] {D4,E3,D2}
		\stone[w, mark = {circle, line = {color = red}}] {C3}
		\mark[custom = {!}] {D3}
	\end{goban}
\end{figure}

To draw this board, we start by placing the stones.

\begin{codeexample}[width=5cm]
	\begin{goban}
		\stones[b] {C2,B3,C4}
		\stones[w] {D4,E3,D2,C3}
	\end{goban}
\end{codeexample}

With the \emph{key} |partial|, we can set the range of the board through its \emph{key} |from|. It takes a value of the form |LN to LN|, where each |LN| is one of a pair of opposite vertices of the rectangle.

\begin{codeexample}[]
	\begin{goban}[partial = B2:E4]
		\stones[b] {C2,B3,C4}
		\stones[w] {D4,E3,D2,C3}
	\end{goban}
\end{codeexample}

To remove the line of the board, we use the \emph{key} |line| of the |background| of the |goban|.

\begin{codeexample}[]
	\begin{goban}[partial = B2:E4, background = {line = false}]
		\stones[b] {C2,B3,C4}
		\stones[w] {D4,E3,D2,C3}
	\end{goban}
\end{codeexample}

Now, to place marks we have the macro
\begin{command}{\mark\opt{\oarg{options}}\marg{intersection}}
\end{command}
and its plural version.

This macro is quite broad and is documented on its own page. For now, we need to know two things:
\begin{itemize}
	\item The mark for the circle is called |circle|.
	\item The mark "!" can be added with |custom|.
\end{itemize}

\begin{codeexample}[]
	\begin{goban}[partial = B2:E4, background = {line = false}]
		\stones[b] {C2,B3,C4}
		\stones[w] {D4,E3,D2}
		\mark[custom = {!}] {D3}
		\stone[w, mark = circle] {C3}
	\end{goban}
\end{codeexample}

We can change the line color of a mark with the \emph{key} |mark/line/color|.

\begin{codeexample}[]
	\begin{goban}[partial = B2:E4, background = {line = false}]
		\stones[b] {C2,B3,C4}
		\stones[w] {D4,E3,D2}
		\mark[custom = {!}] {D3}
		\stone[w, mark = {circle, line = {color = red}}] {C3}
	\end{goban}
\end{codeexample}

\subsection{The End of the Game: Territory}

\begin{figure}[H]
	\centering
	\pgfgoset{profile = wain}
	\begin{goban}[label = {at = {above, left}}]
		\stones[b] {A5,A6,B1,B2,B3,B4,B5,C1,C4,D1,D2,D5,D7,E2,E5,E7,E9,F4,F5,F6,F7,F8,F9,G5,G6,G7,H6,H8,I7}
		\stones[w] {A7,B6,B8,C2,C3,C5,C6,C7,C8,D3,D4,D6,D8,D9,E3,E4,E6,E8,F1,F2,F3,G4,H2,H3,H5,I5,I6}
		\prisoners[b]{H1,I1,I2}
		\prisoner[white] {A1}

		\marks[b, t-circle] {A1,A2,A3,A4,G8,G9,H9,I9,I8,H7}
		\marks[w, t-square] {A9,B9,C9,A8,B7,H4,I4,I3,I2,I1,H1,G1,G2,G3}
		\mark[neutral, t-square] {E1}
	\end{goban}
\end{figure}

Let’s start from the following board:

\begin{codeexample}[]
	\pgfgoset{profile = wain}

	\begin{goban}[label = {at = {above, left}}]
		\stones[b] {A6|-B5|-D1|-E2, C4, E9-|F4, D5-|G7--D7, H6, H8, I7}
		\stones[w] {E8-|C5, B:E6, A7, B8, D9, I6|- H5, H2:3, F1|-C3, C2, D:E4, G4}
	\end{goban}
\end{codeexample}

The next step is to identify the prisoner stones. Prisoners can be marked with the \emph{key} |prisoner| or with the macro
\begin{command}{\prisoner\opt{\oarg{options}}\marg{intersection}}
\end{command}
which also has a plural version.

\begin{codeexample}[width=4.75cm]
	\pgfgoset{profile = wain}

	\begin{goban}[label = {at = {above, left}}]
		\stones[b] {A6|-B5|-D1|-E2, C4, E9-|F4, D5-|G7--D7, H6, H8, I7}
		\stones[w] {E8-|C5, B:E6, A7, B8, D9, I6|- H5, H2:3, F1|-C3, C2, D:E4, G4}

		\stones[b, prisoner]{H1-|I2} % Same as \prisoners[b] {...}
		\prisoner[w] {A1} % Same as \stone[w, prisoner] {...}
	\end{goban}
\end{codeexample}

Now let’s define the territories. This can be done in many ways. In particular, two are implemented for sure: the mark |t-square| and the mark |t-circle|. These marks always take as fill the fill color of the stone they belong to, and as border color and width those of the grid.

\begin{codeexample}[width=4.75cm]
	\pgfgoset{profile = wain}

	\begin{goban}[label = {at = {above, left}}]
		\stones[b] {A6|-B5|-D1|-E2, C4, E9-|F4, D5-|G7--D7, H6, H8, I7}
		\stones[w] {E8-|C5, B:E6, A7, B8, D9, I6|- H5, H2:3, F1|-C3, C2, D:E4, G4}

		\stones[b, prisoner]{H1-|I2}
		\prisoner[w] {A1}

		\marks[b, t-circle]{A1:4, G8|-I9, I8, H7}
		\marks[w, t-square]{G3|-I1|-H4, C9-|A8, B7}
		\marks[t-square, fill = {color = red}] {E1} % Not filled in red: it takes the neutral color.
	\end{goban}
\end{codeexample}

Another way is |\territory| (p.~\pageref{subsec:territory}). With a polygon, it marks the points of that region that have no living stone; with |auto| and the Lua kernel, it finds the territory of each player by itself. |\pgfgoscore| writes the score.

\begin{codeexample}[width=4.75cm]
	\pgfgoset{profile = wain}

	\begin{goban}[label = {at = {above, left}}]
		\stones[b] {A6|-B5|-D1|-E2, C4, E9-|F4, D5-|G7--D7, H6, H8, I7}
		\stones[w] {E8-|C5, B:E6, A7, B8, D9, I6|- H5, H2:3, F1|-C3, C2, D:E4, G4}

		\stones[b, prisoner]{H1-|I2}
		\prisoner[w] {A1}

		\territory[dame]{auto}
	\end{goban}

	Black: \pgfgoscore{black}. White: \pgfgoscore[komi = 6.5]{white}.
\end{codeexample}
